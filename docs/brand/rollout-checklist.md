# Sudar Brand Rollout Checklist (v1)

## Goal
Roll out the unified brand system consistently across product, docs, and external communications without breaking current delivery momentum.

## Phase 1: Foundation
- [ ] Confirm approved logo asset set under `assets/sudar logo`.
- [ ] Confirm token baseline in `docs/brand/design-tokens-v1.md`.
- [ ] Confirm typography availability (Manrope + Inter) in product stacks.
- [ ] Publish brand guideline references to contributor docs.

## Phase 2: Product Surfaces
- [ ] Map Studio theme variables to approved tokens.
- [ ] Map Learn theme variables to approved tokens.
- [ ] Audit key learner-facing views for light/dark parity.
- [ ] Align tutor panel styling and copy tone to guidelines.

## Phase 3: Narrative Surfaces
- [ ] Update README positioning and identity language.
- [ ] Update `docs/MARKETING_DECK.md` with aligned brand and claim-safe proof stack.
- [ ] Update `docs/PITCH_DECK.md` with aligned brand narrative and visual direction notes.
- [ ] Add/refresh launch messaging snippets in outbound channels.

## Phase 4: Governance
- [ ] Add brand review check in PR process for user-facing copy and visuals.
- [ ] Require token usage in new UI components.
- [ ] Add quarterly brand consistency review.
- [ ] Track future changes in versioned guideline updates.

## Legacy Reference Policy
- Keep legacy folder names for compatibility.
- Use Sudar naming in user-facing and outward-facing contexts.
- Avoid introducing new legacy aliases in docs, UI, and marketing.
